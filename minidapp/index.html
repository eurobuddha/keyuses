Minima · Key Security Audit

KeyUses

Minima signatures are stateful: each of your 64 keys must move to a fresh leaf every time it signs. If a seed re-sync set keyuses too low, your node can re-use a leaf it already spent on-chain — which is forgeable. This tool checks, for each key, how many times it has actually signed on-chain and compares that to your node's own counter.

Privacy: in eurobuddha archive mode your 64 public keys are sent to eurobuddha.com, which derives your addresses and returns how often each was spent. Public keys can't move funds, but they do reveal your addresses to that server. For full privacy run your own archive and use My own archive mode.

What is key re-use, and why does it matter?

Minima keys are stateful. Each key is a tree of 262,144 one-time signatures (leaves). Signing safely means using a fresh leaf every time — your node tracks this with a counter.

Re-using a leaf — signing two different transactions with the same one-time signature — is catastrophic: it makes the key publicly forgeable, so anyone can move the funds. It's irreversible; there is no patch, only migrating the funds.

It almost always comes from human error, not a Minima bug:

  • Running two nodes/signers on the same seed (each issues leaves 0,1,2… on its own).
  • Re-syncing from your seed with keyuses set below your true usage.
  • Rolling back wallet state to before signatures you already broadcast.

The fix: one node/counter per seed; on a re-sync set keyuses safely high; and if a key has already re-used, migrate all funds to a brand-new seed and retire the old key.
